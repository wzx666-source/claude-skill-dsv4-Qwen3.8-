# 剧本:长文档翻译(论文 / 教材 / 手册)

> **先圈地**:本剧本只认领**翻译流水线**这一件事 —— 分块、术语、覆盖检查、抽样复审。
> 写译文的语言质量去别的 skill;本剧本解决的是"166 页翻完了,但图里的英文没翻、花了 169 万 token、
> 中途 402 断了要手工收尾"这类**工程问题**。

## 什么时候读这份

| | |
|---|---|
| ✅ | 要翻一份长文档(>20 页 / >2 万字),且要能**续跑**、能**核覆盖率** |
| ✅ | 文档里有图、表格、扫描页 —— 需要把像素里的文字也弄出来 |
| ❌ | 就翻一段话 / 一个摘要 → 直接在本会话说,别上流水线 |
| ❌ | 只是读论文做理解 → `scenarios/research.md` |

## 开口就说

| 你说 | 走到哪 |
|---|---|
| 「把这份论文翻成中文:<pdf>」 | 本剧本,从第 1 步开始 |
| 「翻译跑到一半断了,接着跑」 | 读 manifest,从 `status != done` 的块继续 |
| 「检查一下翻译有没有漏页」 | 第 5 步覆盖检查 |
| 「抽查一下译文质量」 | 第 6 步抽样复审 |

## 核心原则(这次踩坑换来的三条)

### 1. 正文走文本层,图内文字走 OCR —— 两条路成本差三个数量级

| 内容 | 走哪条 | 成本 |
|---|---|---|
| 正文、标题、脚注、参考文献 | **本地文本层**(`pdf_read --no-images` / `pdftotext` / PyMuPDF) | **零 API 成本**,秒级 |
| 图内文字、坐标轴标签、图例、扫描页、手写 | `pdf_read --ocr` 或 `qwen_vision` | 按页计费,慢 |

**不要整本丢给视觉。** 既慢又贵,而且视觉模型会漏读它没"注意"到的正文。
反过来也**不要只做文本层就收工** —— 这次图内英文没进译文,就是漏了第二条路。

```bash
S=~/.claude/skills/qwen-dual-model/scripts

# 先摸清楚这份 PDF 长什么样(零成本)
node $S/pdf_read.mjs 论文.pdf --no-images
#   正文覆盖率: 74/74 页有文字层(100%)
#   ℹ️  --no-images:只做本地文本层抽取,零 API 成本。全部页面都有文字层,可直接用这份 txt。
```

输出里的**「无文字层:第 N 页」**就是必须 OCR 的页。全部有文字层 → 图内文字仍要靠 `--ocr` 单独捞。

### 2. 批量翻译用 DeepSeek,不要用开放式 `qwen_ask`

Qwen 输出价是 Flash 的 10 倍,且 `qwen_ask` 是开放式长生成 —— 这次一次咨询空转 10 分钟零产出。

- **批量正文翻译** → 本会话(DeepSeek)直接做,或派 subagent
- **Qwen 只用在这两处**:① 抽样复审译文(第 6 步)② 图内文字 OCR
- 真要咨询 Qwen,必须带预算:`node $S/qwen_ask.mjs "..." --budget 300`
  (被掐断时返回部分结论 + 退出码 2,不会静默空转)

### 3. 开跑前先 canary,别等跑到一半 402

```bash
node $S/canary.mjs          # 2 秒,两家各一行
node $S/canary.mjs --json   # 给脚本消费
```

- `✅` = 通道通,可以开跑
- `❌ 余额不足/额度用尽` = 去充值,别开跑
- `🟡 通道通,但预算全花在思考上` = 通道没问题,是 `max_tokens` 给太小了

## 流水线(7 步)

```bash
S=~/.claude/skills/qwen-dual-model/scripts
WORK=translations/<文档名>          # 所有中间产物都放这里
```

### 第 0 步:预检(2 秒)

```bash
node $S/canary.mjs
```

### 第 1 步:抽正文(零成本)

```bash
node $S/pdf_read.mjs 论文.pdf --no-images
# → 论文.txt + 覆盖率摘要
```

把「无文字层」的页记下来,第 4 步专门处理。

### 第 2 步:建术语表

**一个文件,所有分块共用。** 这次 12 个 agent 各自重读术语表 = 169 万 token 的主要来源。

```markdown
<!-- $WORK/glossary.md -->
| 原文 | 译文 | 备注 |
|---|---|---|
| proxy correctness signal | 代理正确性信号 | 可商榷,见注 1 |
| reward model | 奖励模型 | 统一用这个,不用"回报模型" |
| RLHF | 基于人类反馈的强化学习(RLHF) | 首次出现给全称,后续用缩写 |
```

> 术语表**自己写**,别丢给模型生成 —— 模型的默认译法恰恰是要统一掉的那个东西。
> 有争议的译法写进「备注」,复审时重点看这几行。

### 第 3 步:分块 + manifest(断点续跑的关键)

分块按**章节**切,不按字数硬切(切在句子中间会丢上下文)。每块 2000–4000 字。

```json
// $WORK/manifest.json
{
  "source": "论文.pdf",
  "glossary": "glossary.md",
  "glossarySha": "a1b2c3d4",
  "chunks": [
    { "id": "01", "title": "Introduction", "pages": [1, 2], "src": "chunks/01.md",
      "out": "out/01.md", "status": "done", "tokens": 12400 },
    { "id": "02", "title": "Method", "pages": [3, 7], "src": "chunks/02.md",
      "out": "out/02.md", "status": "pending", "tokens": null }
  ]
}
```

- `status`:`pending` / `running` / `done` / `failed`
- `glossarySha`:术语表改了哈希就变 → 能查出"哪些块是用旧术语表翻的"
- **断点续跑**:读 manifest,只跑 `status != "done"` 的块。不靠人记 agent ID

> **agent 数量纪律**:一篇论文 **1 个 agent**(正文 + 附录两段),或 **6 个 agent + 共享上下文**。
> 这次 12 个 agent 各自重读术语表和 brief,重复上下文占了约 1/3 的 token。
> 经验值:agent 数 ≈ 章节数,不要按页数派。

### 第 4 步:批量翻译(DeepSeek)

每个 agent 拿到的上下文**只有三样**:术语表、本块原文、上一块的末尾 200 字(接续用)。

```
你是译者。把下面的英文翻译成中文,遵循术语表。
- 术语表:<粘贴 $WORK/glossary.md 全文>
- 上一块结尾(仅供接续,不要翻译):<200 字>
- 本块原文:<...>

要求:保持原文结构(标题层级/列表/表格);公式保留 LaTeX;代码块不译;
不增删内容;专有名词按术语表。
```

翻完立刻更新 manifest 里该块的 `status: done` 和 `tokens`。

### 第 5 步:覆盖检查(零成本,必须做)

```bash
node $S/chunk_check.mjs $WORK/manifest.json
```

检查四件事:
- manifest 里每块的 `out` 文件**是否都存在**
- 每块的 `status` 是否都是 `done`
- 术语表哈希是否与 manifest 记录一致(不一致 = 有块用了旧术语表)
- 输出字符数是否异常偏少(< 原文的 0.3 倍 = 很可能翻漏了)

> 这一步是**可执行的闸门**。只写在文档里、靠人记得做的检查,最后都会被跳过 ——
> 图内英文没翻就是这么漏掉的。

### 第 6 步:抽样复审(Qwen,只审 10–20%)

**不要全量送审。** 全量既贵又慢,而抽样 15% 就能抓出系统性问题。

```bash
# 挑 3-5 个块,每块取开头/中间/结尾各一段
node $S/qwen_review.mjs review out/03.md out/07.md \
  --context "学术论文译文,关注:术语是否与 glossary.md 一致、是否有漏译段落、数字与公式是否忠实" \
  --json
```

看 `issues` 里【高】级的,以及 `partial` 字段(为 true 说明评审被截断,结论不完整)。

**复审的两件事,不要混**:
- 译文是否**忠实**(漏译、错译、数字变了)→ 这是 `review`
- 术语译法**本身**好不好(如 "proxy correctness signal")→ 这个 Qwen 也答不了,
  得人看。所以术语表的「备注」列要写清争议点

### 第 7 步:补图内文字(这次漏掉的那一环)

```bash
# 先看哪些页需要(无文字层的页会被自动优先)
node $S/pdf_read.mjs 论文.pdf --ocr --pages 1-20 --max-img-pages 8
```

OCR 提示词已经内置为「逐字提取,不翻译、不总结」—— 拿到的是**原文文字**,
再交给第 4 步的翻译流程。这样图内文字和正文走的是同一条翻译路径,术语才统一。

> `--max-img-pages` 上限 8。图多的论文分批跑,或用 `--pages` 指定范围。
> 附录常有大量"图内提示词/伪代码截图",**最容易漏**,单独过一遍。

## 成本速查

| 环节 | 走谁 | 相对成本 |
|---|---|---|
| 抽正文 | 本地 | 0 |
| 批量翻译 | DeepSeek Flash | 1× |
| 抽样复审 | Qwen | ~10×/字,但只审 15% |
| 图内 OCR | Qwen 视觉 | 按页,页数少 |

**省钱的三条杠杆**(按效果排序):
1. **减少重复上下文**:agent 数 = 章节数,术语表注入一次,别每个 agent 重读全部
2. **正文绝不用视觉**:文本层免费且更准
3. **复审只抽样**:15% 足够发现系统性问题,全量复审是在为"安心"付 10 倍价钱

---

## 本场景的坑

1. **图内文字默认会被漏掉** —— 文本层只抓"文字对象",图里的字是像素。附录尤其严重。
2. **`max_tokens` 管不住思考量** —— 实测推理模型的 reasoning 单独计。想限时用 `--budget`,不是 `--max-tokens`。
3. **`qwen_ask` 不要用于批量** —— 开放式长生成 + 无预算 = 空转。批量走本会话/agent。
4. **不要靠人记进度** —— manifest 落盘。这次 402 断了之后靠人工收尾,多花了 5–10 分钟。
5. **术语表自己写** —— 让模型生成术语表,等于让它自己跟自己保持一致。
6. **译文风格**:初稿换模型润色会丢文风。**同一模型走完**,润色之后再送 `qwen_review`。
